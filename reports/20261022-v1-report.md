## 遇到的问题与处理

1. 常见 `~/ComfyUI` 路径不存在；通过 Desktop 安装元数据找到实际实例与共享模型目录。
2. 基础 `standalone-env` 无 torch；使用实例 `.venv`。失败日志：comfy-startup.log（未公开）。没有在外部实例安装或修改依赖。
3. 沙箱内 PyTorch 未识别 MPS，回落 CUDA 并报错。沙箱外只读确认 MPS built/available 后启动成功。失败日志：comfy-venv-startup.log（未公开）；不能将该沙箱报错误报为本机模型不可用。
4. 沙箱阻止 MySQL 网络连接，获得执行授权后实际登录成功；未要求用户改虚拟机设置。
5. 系统只有 Java 17/27，项目隔离下载 JDK 21。已有 Maven 使用 HTTP 镜像，改用项目内 HTTPS Central 配置，不修改用户全局设置。
6. 首次测试仓储代理问题经一次修复解决；失败证据保留。

## 未验证 / 未完成边界

- 用户指定的 v1 五项验收没有未完成项；前端、多用户、云 GPU、LoRA 训练、视频生成按要求不实现。
- Docker Compose 本次未运行，其他机器复现尚未验证。
- 真实超时、长期断网、磁盘满、MySQL 断线/重启、ComfyUI 自身重启和历史丢失、压力/长稳、其他模型/设备未实测。超时与临时网络异常只有模拟测试证据。
- 单实例调度；不提供多实例锁和 exactly-once。ComfyUI 历史/队列均丢失时存在重复生成风险。
- 网络不可达时保留 prompt_id 等待核对，不会虚假宣告取消；因此可能超过名义超时。
- `/interrupt` 是全局接口，检查与调用存在竞态，要求专属 ComfyUI 实例；并发 2 测试不等于共享生产实例安全性验证。
- 结果下载/磁盘异常可能触发整个尝试重试，远端可能保留未被本地接收的输出；无自动清理和分布式事务。
- 图片做了 PNG 解码、尺寸、哈希和数据库一致性检查，未进行人工美术质量评审。
