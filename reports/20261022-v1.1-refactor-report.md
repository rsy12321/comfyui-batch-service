## 10 分钟主流程

1. `BatchController → JobService`：校验映射、幂等查询、事务内创建 Job/Task/Event。
2. `TaskWorker.tick → run`：按原队列顺序与并发限制挑选任务。
3. `submit`：在原全局锁范围内先落 prompt_id 和 attempt，再调用远端；保留原提交/取消串行关系。
4. `reconcile → TaskRecovery`：有历史则完成，在队列则继续等，均丢失则进入原有重试。注释明确无法保证 exactly-once。
5. `pollUntilDone → TaskCompletion/ResultStorage`：历史优先、取消确认、超时检查、PNG 下载与结果事务。
6. `handleFailure → TaskFailureHandler`：远端状态不确定时保留 prompt_id；确定失败时保留首次执行加 3 次重试、1/2/4 秒退避及原状态事件。

`TaskLifecycle` 的中文注释明确 JVM 全局监视器的原因与单实例限制。没有将其擅自改成分布式锁或缩小 HTTP 提交锁范围。

## 行为变化：必须单独说明

**没有为了拆包、重命名或拆方法而主动改变业务规则。**但“完全不改变任何行为”与“统一结构化错误体”不能同时满足，故明确区分：

1. 按本次异常处理要求，原 `{"error":"Unauthorized"}`、`{"error":"Not found"}`、Spring 默认错误体等统一为 `{"code":"…","message":"…","details":[]}`。HTTP 状态码保持兼容，新增契约测试覆盖 400/401/404/409/500；旧客户端若解析 error 字段，需要适配。这不是零接口变化。
2. 原来被忽略的 WebSocket 建连、消息处理和恢复查询异常现在记服务端诊断日志；HTTP 响应不包含堆栈、SQL 或真实密钥。日志内容增加属于诊断变化，原历史兜底与继续执行策略不变。
3. OpenAPI 类型描述因具体 record DTO 替代 Object 而更明确，接口路径与成功响应不变。错误模型变化如上。

没有改表结构、配置名/默认值、状态机、最大尝试次数、退避算法、幂等哈希算法、超时/取消顺序、恢复判定、结果路径/哈希计算或图片生成参数。现有单 JVM、全局 interrupt 竞态、历史丢失时可能重复执行等限制仍保留，不借重构顺手修正业务。
